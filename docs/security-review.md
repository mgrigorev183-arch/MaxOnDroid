# Проверка безопасности MaxOnDroid перед выпуском 0.9.0

Дата: 13 ноября 2026. Что проверялось: весь репозиторий (код в `maxondroid/`, тесты, сборка в `packaging/`, рабочие процессы GitHub Actions) и вся история git. Как: сканер шаблонов из навыка проверки безопасности (секреты, опасные функции, внешние адреса), затем чтение кода по чек-листу: ввод данных, файлы и пути, сеть, права, криптография, зависимости, журналы. Проверяемый код при этом не запускался; автоматические тесты проекта запускались отдельно, уже после исправлений.

## Главное

- Срочного нет: живых ключей, паролей и токенов не найдено ни в файлах, ни в истории git. Путей к выполнению чужого кода на компьютере тоже не нашлось: adb и scrcpy запускаются списком аргументов, без командной оболочки Windows.
- Сканер дал 14 срабатываний: 10 HIGH, 1 MEDIUM, 2 LOW, 1 INFO. Все 14 оказались ложными, разбор ниже.
- Чтением кода найдено 4 настоящие проблемы, все низкой серьёзности. Все четыре исправлены в этом выпуске. Ещё 6 пунктов — особенности устройства программы, которые стоит знать; они описаны ниже, менять их не требуется.

## Находки

Слишком большой ответ мог занять память. | Новый модуль `core/net.py`: только HTTPS, в том числе после перенаправлений, ограничение размера, понятные ошибки. ### Учтено, менять не нужно

| № | Серьёзность | Что | Почему так |
|---|---|---|---|
| 5 | INFO | Проверка обновлений обращается к `api.github.com` раз в день. | Уходит только обычный запрос с заголовком `User-Agent: MaxOnDroid/0.9.0`; GitHub видит IP-адрес, как при открытии любой страницы. Никаких данных об устройствах и о пользователе. Ответ разбирается строго, ссылку программа собирает сама (`https://github.com/mgrigorev183-arch/MaxOnDroid/releases/tag/vX.Y.Z`), ничего не скачивает и не запускает. Проверку можно выключить в настройках. |
| 6 | INFO | Установщик не подписан сертификатом. | SmartScreen при первом запуске предупредит. Подлинность файла проверяется по SHA-256, который опубликован на странице выпуска (инструкция в README). Защищает это от повреждённой или подменённой по дороге загрузки; от взлома самого аккаунта GitHub не защищает: злоумышленник с доступом заменил бы и файл, и хеш. |
| 7 | INFO | Папка программы `%LOCALAPPDATA%\Programs\MaxOnDroid` доступна на запись самому пользователю. | Так устроена любая установка без прав администратора (VS Code, Discord и другие). Вредоносная программа, уже запущенная от вашего имени, может подменить файлы, но у неё и так есть доступ ко всем вашим данным. Программа никогда не просит повышения прав. |
| 8 | INFO | Консоль выполняет любые команды adb и shell, которые ввёл пользователь. | Это её назначение. Строка разбирается на аргументы самой программой, cmd.exe и PowerShell не участвуют, поэтому `&`, `|` и `>` не запустят команду на компьютере, а уйдут в adb или в оболочку устройства. Интерактивная оболочка не запускается. |
| 9 | INFO | Имена файлов при скачивании с устройства выбирает сам adb (`adb pull … папка`). | Программа передаёт adb только выбранную вами папку и пути на устройстве, свои пути из имён не строит. Как adb обрабатывает необычные имена (например, с `\`), зависит от adb; встроенная версия — из scrcpy 5.0.1. |
| 10 | INFO | Сетевой adb (`adb tcpip`, порт 5555) открывает устройство для всей сети. | Программа его не включает, а если находит включённым, предупреждает и даёт выключить одной кнопкой. Для Wi-Fi используется беспроводная отладка с сопряжением по коду. |

### Срабатывания сканера, которые оказались ложными

| Серьёзность | Правило | Где | Почему это не проблема |
|---|---|---|---|
| HIGH | py-eval-exec | `maxondroid/ui/app.py` (`app.exec()`) | Это запуск цикла событий Qt (`QApplication.exec`), а не встроенная функция Python `exec`. |
| HIGH | py-eval-exec | `maxondroid/ui/apps_tab.py`, `maxondroid/ui/debloat_tab.py`, `maxondroid/ui/journal_panel.py`, `maxondroid/ui/main_window.py` (`menu.exec(...)`) | Показ контекстного меню Qt (`QMenu.exec`). |
| HIGH | py-eval-exec | `maxondroid/ui/debloat_tab.py`, `maxondroid/ui/main_window.py`, `maxondroid/ui/overview_tab.py`, `maxondroid/ui/package_support.py` (`dialog.exec()`, `box.exec()`) | Показ модального окна Qt (`QDialog.exec`, `QMessageBox.exec`). Встроенные `eval` и `exec` в коде программы не используются нигде, это проверяет и тест границ процессов. |
| MEDIUM | weak-cipher | `maxondroid/data/uad/uad_lists.json` | Это не код, а описание пакета Oppo Share в базе UAD-ng: там сказано, что само приложение Oppo использует слабое шифрование (AES ECB). Программа ничего не шифрует. |
| LOW | http-plain | `tests/test_update.py` | Тест нарочно передаёт адрес `http://` и проверяет, что запрос отклонён (`insecure_url`), а перенаправление на `http://` прерывается. |
| INFO | outbound-host | `tests/test_update.py` | Тот же адрес в тесте; в тестах сеть отключена фикстурой `no_network`, запрос никуда не уходит. |

История git (все коммиты) проверена тем же сканером: ключей и паролей нет, встречаются только те же тестовые адреса `http://`.

## Что исправлено

Все правки внесены прямо в репозиторий: вы попросили проверку перед выпуском вместе с исправлениями. Они вошли в выпуск 0.9.0 (коммит «Stage 5: update check, security fixes, …»):

- `maxondroid/ui/common.py`, `ui/package_support.py`, `ui/overview_tab.py` — простой текст вместо автоопределения HTML (находка 1);
- `maxondroid/core/console.py`, `ui/console_tab.py` — код сопряжения скрыт в истории консоли (находка 2);
- `maxondroid/core/net.py` (новый), `core/uad.py`, `core/update.py` — только HTTPS, ограничение размера (находка 3);
- `.github/workflows/tests.yml`, `.github/workflows/release.yml`, `.github/dependabot.yml`, `packaging/requirements-build.txt` — закрепление действий и пакетов, минимальные права (находка 4).

К каждому исправлению есть тесты: `tests/test_update.py`, `tests/test_ui_update.py`, `tests/test_console.py`. Весь набор тестов проходит на Linux и на Windows в GitHub Actions.

## Чего проверка не покрывает

- Поиск по шаблонам находит не всё. Логика программы проверена только чтением, без фаззинга и без атакующих тестов на живых устройствах.
- Известные уязвимости в зависимостях (PySide6/Qt, Python, segno, PyInstaller, scrcpy, adb) по базам CVE здесь не проверялись: доступа к этим базам у проверки не было. Версии закреплены, обновления предлагает Dependabot.
- Код самих adb и scrcpy не проверялся: они используются как готовые программы из официального выпуска scrcpy, сверенного по SHA-256.
- Безопасность Android-устройств (что разрешено отладке по USB и Wi-Fi) зависит от самих устройств и в проверку не входила.

## Что делать дальше

- Отзывать ключи не нужно: их нет ни в коде, ни в истории.
- Включить в настройках репозитория на GitHub «Secret scanning» и «Push protection» (Settings → Code security), а Dependabot уже подключён файлом `.github/dependabot.yml`. Предложения Dependabot для `packaging/requirements-build.txt` сливать, только когда хеши обновлены вместе с версиями.
- Если начнёте коммитить сами, поставить [Gitleaks](https://github.com/gitleaks/gitleaks) в pre-commit, чтобы ключ не попал в коммит даже случайно.
- Скачивая установщик, сверять SHA-256 со страницей выпуска (README, раздел «Установка»).
- Когда появится возможность, подписать установщик сертификатом: тогда пропадёт предупреждение SmartScreen и подмена файла станет заметнее.
